# Lab 01: Data Representation

## Завдання 1. Розміри типів даних

**Таблиця розмірів типів:**

| Тип | Розмір, bytes | Розмір, bits |
| :--- | :--- | :--- |
| `char` | 1 | 8 |
| `short` | 2 | 16 |
| `int` | 4 | 32 |
| `long` | 8 | 64 |
| `long long` | 8 | 64 |
| `float` | 4 | 32 |
| `double` | 8 | 64 |
| `void *` | 8 | 64 |

**Відповіді на питання:**

1. **Чи всі типи займають однакову кількість пам'яті?**
   Ні, розмір залежить від типу та архітектури системи. Наприклад, `char` завжди займає 1 байт, тоді як `double` або вказівники можуть займати 8 байтів.

2. **Скільки бітів займає int у вашому середовищі?**
   32 біти, оскільки `sizeof(int)` повертає 4 байти, а 4 байти × 8 бітів = 32 біти.

3. **Який розмір має вказівник void *?**
   8 байтів.

4. **Що розмір вказівника говорить вам про архітектуру середовища?**
   Розмір вказівника у 8 байтів вказує і підтверджує на те, що ми працюємо у 64-бітному середовищі, оскільки 8 байтів це 64 біти.

## Завдання 2. Decimal → Hexadecimal

**Таблиця представлення значень:**

| Decimal | Hexadecimal | Binary |
| :--- | :--- | :--- |
| 10 | 0xA | 0000 1010 |
| 65 | 0x41 | 0100 0001 |
| 127 | 0x7F | 0111 1111 |
| 255 | 0xFF | 1111 1111 |
| 256 | 0x100 | 0001 0000 0000 |
| 1024 | 0x400 | 0100 0000 0000 |

**Відповідь на питання:**
**Чому 65, 0x41 та 01000001 можуть представляти одне й те саме числове значення?**
Тому що комп'ютер на фізичному рівні зберігає дані як послідовність електричних станів. Десяткова (65), шістнадцяткова (0x41) та двійкова (01000001) форми — це лише різні системи числення, тобто різні способи відображення однієї й тієї самої послідовності з 8 бітів у пам'яті.

## Завдання 3. Виведення бітів

**Чому функція починає перевірку з біта 7, а не з біта 0?**
Тому що ми звикли читати числа зліва направо: від найстаршого розряду до наймолодшого. У байті біт 7 є найстаршим значущим бітом, а біт 0 — наймолодшим. Щоб надрукувати двійкове число у звичному для людини порядку зліва направо, потрібно почати виводити біти починаючи з 7-го і закінчуючи 0-м.

## Завдання 4. Символ — це також число

**Таблиця символів:**

| Character | Decimal | Hex |
| :--- | :--- | :--- |
| A | 65 | 0x41 |
| B | 66 | 0x42 |
| a | 97 | 0x61 |
| 0 | 48 | 0x30 |
| 9 | 57 | 0x39 |

**Відповідь на питання:**
**Що фактично зберігається у змінній `char c = 'A';`? Літера A чи числове значення?**
Фактично в пам'яті зберігається числове значення адже 65 у десятковій системі, або двійкове `01000001`. Комп'ютер не розуміє літер, він оперує лише числами. Літера 'A' — це лише візуальна інтерпретація цього числа згідно зі стандартом кодування ASCII, яка застосовується, коли ми просимо програму вивести значення як символ.

## Завдання 5. Signed та Unsigned

**Прогноз для -1:** Очікується `11111111` (`0xFF`), оскільки від'ємні числа зберігаються у доповнювальному коді (two's complement).

**Відповідь на питання:**
**Як можливо, що `11111111` може означати `255` і водночас `-1`? Що визначає значення цієї послідовності бітів?**
Самі по собі біти не мають сенсу. Їхнє значення визначається типом даних, який вказує процесору, як саме читати ці 8 бітів. Якщо тип `uint8_t`, усі 8 бітів формують додатне число 255. Якщо наприклад тип `int8_t`, то найстарший біт діє як знаковий, і за правилами доповнювального коду значення інтерпретується як -1.

## Завдання 6. Дослідження межі unsigned integer

**Прогноз:** `255 + 1` у `uint8_t` дорівнюватиме `0`.

**Пояснення результату:**
Тип `uint8_t` має розмір рівно 8 бітів, що дозволяє зберігати значення від 0 до 255. Коли до 255 додається 1, математичний результат вимагає 9-го біта (`1 00000000`). Оскільки у нас є лише 8 бітів пам'яті, тоді дев'ятий біт просто відкидається, і в пам'яті залишаються вісім нулів. Це називається переповненням, тому результат стає `0`.

## Завдання 7. Подивимося безпосередньо в пам'ять

**Гіпотеза перед запуском:** Очікувався Варіант B (78 56 34 12), оскільки ми працюємо на архітектурі x86_64, яка використовує формат little-endian.
**Фактичний результат:** Програма вивела байти у порядку: 78, 56, 34, 12.

## Завдання 8. Визначення Endianness

**Відповіді на питання:**
1. **У якому напрямку змінюються адреси?**
   Адреси послідовно збільшуються, тобто кожен наступний байт має адресу на 1 більшу за попередню.
2. **Який байт знаходиться за найменшою адресою?**
   Байт `0x78` наймолодший значущий байт.
3. **Чому це свідчить про little-endian?**
   Система Little-endian зберігає найменш значущий байт за найменшою адресою пам'яті. Саме це й можна спостерігати: `78` знаходиться першим.
4. **Чи змінилося саме число 0x12345678, чи змінився лише порядок його байтів у пам'яті?**
   Саме числове значення `0x12345678` не змінилося. Змінився лише фізичний порядок розміщення складових байтів цього числа у пам'яті комп'ютера.

## Завдання 9. Один набір бітів — різні інтерпретації

**Таблиця інтерпретацій для `01000001`:**

| Інтерпретація | Значення |
| :--- | :--- |
| Binary | 01000001 |
| Hexadecimal | 0x41 |
| Unsigned decimal | 65 |
| ASCII character | A |

**Чому комп'ютеру недостатньо знати лише біти, щоб визначити значення даних?**
Самі по собі біти не мають вбудованого сенсу — це просто електричні стани у пам'яті. Щоб зрозуміти, що означає конкретна послідовність бітів, комп'ютеру потрібен контекст, який у мовах програмування задається типом даних. Саме тип визначає інтерпретацію: чи читати ці 8 бітів як символ (`char`), як беззнакове число (`uint8_t`), чи як частину більшої структури. Без вказівки типу неможливо сказати, чи `01000001` — це літера "A", чи число 65.

## Додаткове завдання: Дослідження 32-бітного значення

**Очікувані та фактичні результати:**
Було створено програму `inspect32.c`, яка досліджує 32-бітне число `0x12345678`.

* **Value:** `0x12345678`
* **Size:** 4 bytes

**Розташування в пам'яті (Memory):**
* byte 0: `0x78`
* byte 1: `0x56`
* byte 2: `0x34`
* byte 3: `0x12`

**Порядок байтів (Byte order):** `Little-endian`

**Пояснення динамічного визначення Endianness:**
Програма визначає порядок байтів не жорстко заданим текстом, а алгоритмічно. Вона порівнює значення, яке лежить за першою адресою в пам'яті, із наймолодшим значущим байтом самого числа, отриманим через побітове «І»: `value & 0xFF`, що дорівнює `0x78`. Оскільки за найменшою адресою пам'яті лежить саме наймолодший байт, програма успішно підтверджує, що наша система на базі архітектури x86_64 використовує порядок Little-endian.
