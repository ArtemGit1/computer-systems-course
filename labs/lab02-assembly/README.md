# Lab 02: Assembly

## Підготовка

**Які операції повинен виконати CPU для реалізації `int result = a + b;`?**
Процесор має завантажити значення змінних з оперативної пам'яті у свої внутрішні комірки (регістри), виконати математичну операцію додавання за допомогою арифметико-логічного пристрою, а потім зберегти отриманий результат назад у пам'ять, виділену для змінної `result`.

## Завдання 1. Отримуємо Assembly

**Відповіді на питання:**

1. **Чи кожному рядку C відповідає рівно одна Assembly-інструкція?**
   Ні, одному рядку C зазвичай відповідає кілька машинних інструкцій.
2. **Чи бачите ви в Assembly змінні з назвами a, b, result?**
   Ні, замість імен змінних процесор оперує адресами пам'яті (наприклад`[rbp-4]`) та регістрами (наприклад `eax`).
3. **Скільки Assembly-інструкцій приблизно відповідає тілу main()?**
   Близько 10–15 інструкцій, включаючи підготовку стекового кадру, виділення пам'яті, самі обчислення, виклик `printf` та інструкцію `ret`.
4. **Чи присутня операція додавання?**
   Так, присутня у вигляді інструкції `add`.

## Завдання 2. Знаходимо арифметичну операцію

**Таблиця операцій:**

| C | Основна Assembly-інструкція |
| :--- | :--- |
| `a + b` | `add` |
| `a - b` | `sub` |
| `a * b` | `imul` |

**Пояснення:** 
Після зміни арифметичної операції в C, загальна структура функції залишається незмінною. Змінюється лише одна конкретна інструкція, яка відповідає за обчислення.

## Завдання 3. if на машинному рівні

**Відповідність C та Assembly:**

* `if (a > b)` → `cmp` (порівняння значень) та `jle` (умовний перехід, якщо менше або дорівнює, до блоку else).
* `return a` → `mov eax, ...` (запис значення `a` в регістр результату).
* `else` → Мітка в Assembly (наприклад, `.L2:`), куди відбувається перехід, якщо умова хибна.
* `return b` → `mov eax, ...` (запис значення `b` в регістр результату).

**Контрольне питання:**
*Чи існує машинна інструкція `IF`?*
Ні, на апаратному рівні не існує єдиної команди "if". Процесор реалізує цю конструкцію у два кроки: спочатку виконує математичне порівняння інструкцією `cmp` яка встановлює спеціальні прапорці стану процесора, а потім використовує інструкцію умовного переходу, щоб перестрибнути на іншу адресу в пам'яті залежно від встановлених прапорців.

## Завдання 4. Цикл

**Відповіді на питання:**

1. **Яка інструкція виконує порівняння?** 
   Інструкція `cmp` (порівнює лічильник `i` з лімітом `n`).
2. **Яка інструкція реалізує перехід?** 
   Умовні переходи наприклад `jle`, та безумовні переходи наприклад`jmp`.
3. **Чи існує в отриманому Assembly поняття for?** 
   Ні. Для процесора немає різниці між `for`, `while` чи `do-while`. Будь-який цикл розгортається у лінійну послідовність інструкцій з мітками та командами переходу, які змушують процесор повертатися назад.
4. **Як CPU визначає, що цикл потрібно повторити?** 
   Після виконання тіла циклу та збільшення лічильника, процесор знову виконує порівняння (`cmp`). Якщо умова все ще виконується, інструкція умовного переходу скеровує процесор на адресу початку тіла циклу.
   
## Завдання 5. Виклик функції

**Відповіді на питання:**

1. **Де знаходиться виклик `calculate`?**
   У тілі функції `main`, за допомогою інструкції `call calculate`.
2. **Де починається код `calculate`?**
   Одразу після мітки `calculate:` у файлі.
3. **Де функція завершується / Де знаходиться `ret`?**
   В кінці блоку інструкцій функції `calculate` стоїть інструкція `ret`, яка повертає керування туди, звідки функцію було викликано.
4. **Який регістр містить результат функції перед поверненням?**
   Регістр `eax` (відповідно до стандартної конвенції викликів x86-64 для цілочисельних значень).

**Чому після call CPU повинен мати спосіб визначити, куди повернутися?**
Тому що одну й ту саму функцію можна викликати з десятків різних місць у програмі. Процесору потрібно запам'ятати точну адресу інструкції, яка йде одразу після поточного виклику `call`, щоб продовжити виконання програми без збоїв.

## Завдання 6 та 7. Machine code

**Приклади машинних інструкцій з `objdump`:**

| Address | Machine-code bytes | Assembly |
| :--- | :--- | :--- |
| `0x113d` | `01 d0` | `add eax, edx` |
| `0x1145` | `c3` | `ret` |
| `0x1120` | `55` | `push rbp` |

**Відповіді на питання:**

1. **Що насправді зберігається у виконуваному файлі: текст Assembly чи machine code?**
   У виконуваному файлі зберігається виключно machine code, тобто шістнадцяткові байти, які відповідають нулям та одиницям.
2. **Навіщо тоді objdump показує Assembly?**
   Для зручності людини. `objdump` читає машинні байти і перекладає їх назад у зрозумілому форматі, оскільки читати "сирі" байти вкрай важко.
3. **Чи всі машинні інструкції x86-64 мають однакову кількість байтів?**
   Ні. Архітектура x86-64 має інструкції змінної довжини. Деякі інструкції займають 1 байт, а інші можуть займати 5, 7 або навіть більше байтів залежно від складності та операндів.
4. **Чому людині зручніше аналізувати Assembly, ніж байти machine code?**
   Assembly використовує текстові команди (`mov`, `add`) та назви регістрів (`eax`, `rbp`), які відображають логіку дій процесора, тоді як машинний код — це суцільний потік чисел без очевидного візуального значення.

## Завдання 8. Експеримент з оптимізацією

Компілятор з прапорцем `-O2` значно спрощує Assembly-код. Він прибирає зайві операції зі стеком, оптимізує передачу параметрів і використовує регістри напряму, що робить код коротшим та швидшим.

## Завдання 9. Передбачте результат компілятора

**Прогноз:** Варіант B (Одразу поверне 30).

**Пояснення результату:** Компілятор має право замінити `10 + 20` готовим значенням `30`, оскільки це константи, відомі під час компіляції. Це правило оптимізації не змінює логіку чи спостережувану поведінку програми, але звільняє CPU від виконання зайвої арифметики під час роботи.

## Контрольні питання

1. **Що таке ISA?** Instruction Set Architecture (архітектура набору команд) — це набір машинних інструкцій, які розуміє і може виконувати конкретний процесор.
2. **Чому CPU не може безпосередньо виконувати C-код?** CPU розуміє лише бінарні електричні сигнали. C-код — це високорівнева абстракція у вигляді тексту, створена для зручності людей.
3. **У чому різниця між Assembly та machine code?** Assembly — це текстові команди, а machine code — це їхній прямий бінарний/шістнадцятковий еквівалент, який читає процесор.
4. **Що робить параметр GCC -S?** Зупиняє процес компіляції після генерації Assembly-коду, не перетворюючи його на об'єктний чи виконуваний файл.
5. **Навіщо ми використовували -O0?** Щоб вимкнути оптимізацію і побачити лінійну, незмінену відповідність між нашим C-кодом і згенерованими Assembly-інструкціями.
6. **Що таке operand?** Це значення, змінна або регістр, з яким виконує дію інструкція.
7. **Для чого використовується mov?** Для переміщення даних між регістрами, або між регістрами та оперативною пам'яттю.
8. **Яку роль виконує cmp?** Віднімає один операнд від іншого (не зберігаючи результат), щоб встановити прапорці стану процесора для наступних умовних переходів.
9. **Як на машинному рівні реалізується if?** За допомогою комбінації інструкції порівняння та інструкції умовного переходу.
10. **Як реалізується цикл?** Як послідовність інструкцій, що завершується умовним переходом назад на мітку початку циклу, якщо умова все ще виконується.
11. **Для чого потрібна інструкція call?** Для виклику функції. Вона зберігає адресу повернення на стек і передає керування на адресу функції.
12. **Для чого потрібна ret?** Для повернення з функції. Вона забирає адресу зі стеку, яку туди поклав `call`, і продовжує виконання з того місця.
13. **Чому одному рядку C не обов’язково відповідає одна машинна інструкція?** Рядок C часто є високорівневою абстракцією. Наприклад, виклик `printf` або проста операція можуть вимагати завантаження даних з пам'яті, обчислень і збереження результату.
14. **Що показує objdump -d?** Дизасембльований код програми, тобто машинні байти разом з їх текстовим представленням в Assembly.
15. **Чому Assembly, отриманий з -O0 та -O2, може суттєво відрізнятися?** Оптимізатор `-O2` може видаляти непотрібні змінні, спрощувати математику, зберігати дані у регістрах замість стеку та вбудовувати функції для максимальної продуктивності.
16. **Чи може компілятор повністю видалити частину написаного програмістом C-коду? За яких умов?** Так, якщо оптимізатор бачить, що цей код ніяк не впливає на кінцевий результат.
